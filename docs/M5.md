## Deployment prerequisites

The Vercel CLI is installed but logged out, and this repository is not linked to a Vercel project. Production Redis/email credentials are not available in the local environment. No deployment has been published.

1. Sign in with `vercel login`, then use `vercel link` to select the intended account/project (or create `gift-confirm`).
2. Configure production variables in Vercel, keeping secrets out of Git and chat:

   - `APP_URL`: the project's stable HTTPS origin; verification links and origin checks use it.
   - `UCP_PROFILE_URL`: the value supplied in `.env.example`.
   - `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`: the project's persistent database.
   - `NEXT_PUBLIC_GIVER_NAME`: the giver name for the prototype.
   - `RESEND_API_KEY` and `EMAIL_FROM`: a sending key and verified sender domain.
   - `CRON_SECRET`: at least 32 random characters.
   - Remove `EMAIL_MODE=preview` from production. `ANTHROPIC_API_KEY` is optional; catalog-based photo cues remain available without it.

3. Pull production configuration to an ignored file for preflight:

   ```bash
   vercel env pull .env.production.local --environment=production
   node --env-file=.env.production.local --import tsx scripts/check-deploy.ts
   npm run build
   vercel --prod
   ```

   The preflight validates required configuration and pings Redis. It never sends email. `/api/health` checks configuration presence, not provider uptime; the Redis ping is separate.

4. Configure a scheduler to call `GET /api/jobs/notifications` every 5–10 minutes with `Authorization: Bearer <CRON_SECRET>`. Verify the chosen hosting plan supports that frequency before enabling it. No scheduled cloud task has been created. See [EMAIL.md](EMAIL.md) for retry limits.
5. Confirm the deployed health response has `ok: true`, `productionReady: true` and `storage: "upstash"`. Create a gift, reload it, and verify it remains available across requests. Test one verification email using a real address you control and check delivery in the email provider.
6. Seed a production demo through the deployed API, or create it in your browser so you retain giver access:

   ```bash
   DEMO_BASE_URL=https://your-project.vercel.app npm run demo:seed
   ```
